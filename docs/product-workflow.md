# Crave Hunt Product Workflow

## Discovery loop
RAW SIGNAL → SOURCE CAPTURE → ENTITY EXTRACTION → DEDUPLICATION → GEO NORMALISATION → CLAIM CHECK → COMMUNITY CROSS-CHECK → FIELD REVIEW → PUBLISH → FRESHNESS CHECK → ARCHIVE/UPDATE.

## Core surfaces
1. Crave Now — immediate dish-led discovery.
2. Explore — browse by dish, locality, pincode, budget, time, mood and cuisine.
3. Hunt — submit something missing; include link, location and personal context.
4. Food Library — reels, YouTube, articles, Reddit/X/community references.
5. Patna Food Atlas — places + dishes + neighbourhoods + historical context.
6. Legacy — culinary history, migration, markets, institutions and disappearing foods.
7. Beginner's Patna — first 5 meals, one-day food route, budget routes, vegetarian/non-veg routes, student routes.
8. Events — upcoming/ongoing/past food-related events, fairs, pop-ups and food walks; link out rather than pretending to own event information.
9. Saved Hunts — user's personal food trail.
10. Field Notes — structured reviews after actually visiting.

## Trust model
Never convert a single social post into fact. Keep source provenance. Separate editorial review, community sentiment and objective facts. Track last checked date for hours, prices, location and status.

## Future ranking signals
Do not use a single star score. Build a composite evidence layer from recency, number of independent mentions, reviewer confidence, repeat mentions, dish-specific consensus, price accuracy, location certainty and freshness.

## Research expansion
Search in waves: broad web → Google/Maps-like place discovery → Reddit/community threads → X/social → YouTube/Instagram → official tourism/heritage → newspapers → archives. Deduplicate by canonical place/entity ID. Preserve every source even when multiple sources point to the same entity.
